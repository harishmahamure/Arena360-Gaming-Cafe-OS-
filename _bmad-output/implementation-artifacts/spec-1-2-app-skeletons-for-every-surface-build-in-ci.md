## Intent

**Problem:** No Arena 360 surface has an app yet. Every later UI story would otherwise start by setting up its own app, and that is where structural drift starts.

**Approach:** Create one shared Svelte UI workspace package with a `Placeholder` component. Add eight app skeletons that render it:
- Tauri: Hub and Kiosk
- SvelteKit static: Kitchen
- SvelteKit on Cloudflare: Owner PWA, partner portal, admin and onboarding
- Astro: marketing site

CI builds each app in its own job named after the app. `ci-ok` depends on those jobs.

## Boundaries & Constraints

**Always:**
- **Layout and package names:**
  - `packages/ui` is `@arena/ui`. It exports `Placeholder.svelte`, which takes a `surface: string` prop and renders "Arena 360" plus the surface name. Its export map exposes `.` and `./Placeholder.svelte`, with the `svelte` condition.
  - The apps are `apps/{hub,kiosk,kitchen,owner,partner,admin,onboarding,marketing}`, named `@arena/<dir>`. Each app depends on `"@arena/ui": "workspace:*"` and renders `Placeholder` on its root page.
- **Dependency pins:** every JS framework dependency uses `catalog:`.
  - Add to the catalog, with matching README pin rows: `@sveltejs/vite-plugin-svelte` 7.3.1, `wrangler` 4.152.0 and `svelte-check` 4.7.7.
  - Add `tauri-build` to `[workspace.dependencies]` as an exact `=` pin, with a README row. Use the version `@tauri-apps/cli` 2.12.4's `init` emits for tauri 2.12.5.
  - Run `pnpm check:pins` to confirm the README and manifests agree.
- **Tauri apps:**
  - Hub and Kiosk use SvelteKit with `adapter-static` in SPA mode (`fallback: 'index.html'`, `ssr = false`).
  - Each has `src-tauri/` as a Cargo workspace member (add `apps/*/src-tauri` to `members`), using `tauri.workspace = true` and `tauri-build.workspace = true`.
  - Crate names are `arena-hub-ui` and `arena-kiosk-ui`, each a bin with one passing test.
  - `tauri.conf.json` sets identifier `in.arena360.hub` / `in.arena360.kiosk`, `frontendDist: "../build"` and the `beforeBuildCommand`. Commit placeholder icons generated by `tauri icon`.
  - No plugins and no capabilities beyond the default.
- **Kitchen** uses `adapter-static` with prerendering.
- **Cloudflare apps:** Owner, partner, admin and onboarding use `adapter-cloudflare`, plus a minimal `wrangler.jsonc` (Workers static assets: `assets.directory` pointing at the adapter output, a `compatibility_date`). No deploy step.
- **Marketing** is Astro 7.4 with the `@astrojs/svelte` integration. `src/pages/index.astro` renders `<Placeholder surface="Marketing" />` from `@arena/ui`. Output is static.
- **Package scripts:**
  - Each app has `build`.
  - Each Tauri app also has `tauri` (it runs `tauri` from `@tauri-apps/cli`).
  - The root gains `build`, which is `pnpm -r --filter "./apps/*" build`.
- **Branch surfaces bundle everything.** Hub, Kiosk and Kitchen load no remote fonts, CDN assets or scripts at runtime.
- **CI** gets one job, `build`, with a `fail-fast: false` matrix of `{app, os}`, named `build (<app>)`:
  - Web apps and marketing run on ubuntu-latest: `pnpm install --frozen-lockfile`, then `pnpm --filter @arena/<app> build`.
  - Hub and Kiosk run on windows-latest: frontend build, then `pnpm --filter @arena/<app> tauri build --no-bundle`.
  - `ci-ok.needs` adds `build`.
  - The existing ubuntu Rust job installs the Tauri Linux system packages (`libwebkit2gtk-4.1-dev`, `libayatana-appindicator3-dev`, `librsvg2-dev`, `libxdo-dev`, `libssl-dev`, `build-essential`) before clippy and test, so `cargo test --workspace` still covers the Tauri crates.

**Never:**
- Real screens, routing, i18n, design tokens (Story 1.4) or generated types (Story 1.3).
- PWA service worker or manifest, Tauri updater wiring, signing, installers or bundles.
- Deploying anything.
- Hand-written protocol types.
- Raw hex colours in app code. Any styling uses neutral CSS without colour literals.

## Code Map

- `Cargo.toml` -- `members = ["crates/*"]`. Extend it and add the `tauri-build` pin next to the `tauri` pin. Keep the existing pins.
- `pnpm-workspace.yaml` -- `catalog:` holds the 1.1 pins. Add the three new entries. `packages:` already covers `apps/*` and `packages/*`.
- `README.md` -- pin table (`| Item | Version | Source |`, Cargo values written as `=x.y.z`) and the Layout section. Add the new rows and an Apps table.
- `scripts/check-pins.mjs` -- requires catalog entries to be bare semver and Cargo entries to be `=x.y.z`. Reads only the root `Cargo.toml` `[workspace.dependencies]`, which is why src-tauri crates must use `workspace = true`.
- `.github/workflows/ci.yml` -- jobs are `rust`, `checks` and `ci-ok`. `ci-ok` uses `if: always()` and fails on any failure, cancellation or skip in `needs`. Add `build`, and the apt step to the `rust` job (ubuntu only, via `if: runner.os == 'Linux'`).
- `.gitignore` -- already ignores `.svelte-kit/`, `build/`, `dist/`, `.astro/` and `.wrangler/`. Add `apps/*/src-tauri/gen/` if `tauri` generates it.
- `.prettierignore` -- add generated outputs if prettier would scan them (for example `apps/*/src-tauri/icons`). Ensure `pnpm format:check` covers the new sources.
- Leave alone: `scripts/check-layers.mjs`. The new crates are unrestricted, so no rule change is needed.

## Implementation Notes

- SvelteKit 3 rejects `svelte.config.js` (`config_file_unsupported`); Kit options (the adapter) are passed to `sveltekit({ adapter })` in each `vite.config.js`. App `tsconfig.json` files extend `$app/tsconfig` as Kit 3 requires.
- `tauri-build` pin is `=2.7.4` (what `@tauri-apps/cli` 2.12.4 `init` emits alongside tauri 2.12.5).
- Tauri configs set `devUrl` (hub 5173, kiosk 5174) so `cargo test`/`clippy --workspace` compile without a built frontend; `bundle.active` is false; `csp` is `default-src 'self'; img-src 'self' data:; style-src 'self' 'unsafe-inline'` (Tauri hashes SvelteKit's inline bootstrap script into it at build time); no `version` key, so Tauri uses the Cargo version. No `capabilities/` directory: the CLI does not require one and no IPC is used.
- `tauri icon` output is committed minus the `android/` and `ios/` sets (desktop only).
- pnpm 12 added `minimumReleaseAgeExclude` for `wrangler@4.152.0` and its `miniflare` beta (released the day before this story) and `allowBuilds` for `esbuild` and `workerd` to `pnpm-workspace.yaml`.
- So `pnpm format:check` covers `.svelte` and `.astro` sources, the root gained `prettier-plugin-svelte` 4.1.1 and `prettier-plugin-astro` 1.1.1 (exact pins, like `prettier`) plus `svelte` (`catalog:`) as its peer.
- Each SvelteKit app also has `dev`, `preview` and `check` (`svelte-check`) scripts; CI runs `check` before `build`. Fixed dev ports: hub 5173, kiosk 5174, kitchen 5175, owner 5176, partner 5177, admin 5178, onboarding 5179, marketing 5180.
- `check-pins.mjs` also fails on a catalog package not referenced as `catalog:`, or an `@arena/*` package not referenced as `workspace:*`, in the root, `apps/*` or `packages/*` manifests.
