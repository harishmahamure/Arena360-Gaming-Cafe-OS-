# Spine Pair Review — Arena 360

## Overall verdict
The pair is well-built where the design effort went: the Kiosk player surfaces and the Hub floor view. Tokens are complete (every colour has hex plus a `-hc` twin), every `{ref}` resolves, all 29 named components appear in both spines, and all 8 source journeys plus the new Journey 9 have flows with a named protagonist and a climax. The contract gets thinner further from the floor view. POS, shift close, inventory, Owner app, onboarding and partner portal have almost no component or state spec. The floor-tile state model leaves out states the sources require (unassigned, paused, console). Several load-bearing decisions are still parked as `[NOTE FOR UX]`: kiosk when the Hub is unreachable, Android-phone Hub POS layout, and tier gating as hidden vs locked. No critical findings. The high findings are where downstream developers would otherwise have to make up the answer.

## 1. Flow coverage — adequate
Checked: the 8 journeys in `docs/Arena360 — User Journeys.md` (table + sections 1–7), the PRD requirement areas (Kiosk app, Console management, Owner app, Onboarding, Hub modules), and EXPERIENCE.md Key Flows 1–9 for protagonist, numbered steps, climax and failure path. Journeys 1–9 all have a named protagonist, numbered steps and a bolded climax. Failure paths exist for 1, 2, 3, 4, 6. Journey 8 and 9 failures are `[NOTE FOR UX]`. Journey 5 and 7 handle their branches inside the steps.
### Findings
- **high** Console management (PRD "Console management — MVP manual timed devices": consoles on floor view, Hub-side timer and warnings, "time-up shows alert on Hub, staff walk over") has no flow and no floor-tile or alert treatment. The v1.1 Pi "Start by QR" path is in IA only, with no flow (EXPERIENCE.md § Key Flows; § State Patterns). *Fix:* Add a short "Console session (Rohit, PS5 TV 3)" flow covering staff start, Hub-side warning and the time-up alert. Add console as a device kind on `floor-tile`. Add a v1.1 QR-start flow or explicitly defer it.
- **medium** Kiosk sign-up has no flow and no component, although it is the entry point for every new prepaid player (PRD Kiosk "Sign-up" row). Open Question 5 is partly stale (see §7) (EXPERIENCE.md § IA Kiosk row; § Open Questions 5). *Fix:* Add a sign-up sub-flow under Journey 3 (fields, duplicate-username/phone refusal copy, consent) and a `signup-panel` or reuse `login-panel` explicitly.
- **medium** Journey 1, step 7 says "Steps 6–8 skippable", but the spine renumbered the steps: spine 6 = kiosks pair, 7 = groups/plans/invite, 8 = test session. As written, the test session reads as skippable, which contradicts the source (EXPERIENCE.md § Journey 1 step 7). *Fix:* Name the skippable steps ("Kiosk pairing, groups and plans, staff invite can be skipped and finished from the Hub").
- **low** Journey 1 drops the source's Printer-and-payments step and the "ad consent on Free" go-live item. Journey 3 drops the lock-screen branch ("allow-listed processes closed if configured; otherwise game left paused for staff"). Journey 4 drops "pay an order immediately from the HUD by wallet" (EXPERIENCE.md § Key Flows 1, 3, 4). *Fix:* Add one clause each, or a pointer that these live in the source.
- **low** The PRD kiosk Warnings row includes a "low balance" warning. The spine covers only 10/5/1 min (EXPERIENCE.md § Component Patterns `hud-toast`). *Fix:* Add a low-balance trigger to `hud-toast`.

## 2. Token completeness — adequate
Checked: all 66 colour tokens, 17 typography roles, 6 radii and 12 spacing tokens in the DESIGN.md frontmatter. Also every `{path}` reference in the DESIGN.md components, the DESIGN.md prose and the EXPERIENCE.md prose (`{colors.warning}`, `{colors.state-*}`, `{colors.state-free}`, `{colors.bg}`, `{spacing.touch-min}`, `{components.scrim}`). All resolve. Every colour has a hex value. Every themable colour has an `-hc` pair. `scrim-base` has no pair, which is correct because the scrim is removed in HC. Contrast ratios are stated for text/bg, on-accent, the six states on `hub-tile`, the chips and the HUD toast.
### Findings
- **high** No focus-ring token or visual spec, although EXPERIENCE requires "visible focus rings" for the keyboard-operable counter flow and a "focus outline" on `game-tile` select. The PRD acceptance criterion is "counter flow possible without mouse" (DESIGN.md frontmatter `colors` / § Components; EXPERIENCE.md § Accessibility Floor, § Component Patterns `game-tile`). *Fix:* Add `focus-ring` / `focus-ring-hc` colours plus width/offset (e.g. a `focus` component token) and state its contrast against `bg`, `hub-tile` and `surface`.
- **medium** Interactive state visuals (hover, pressed, disabled) are undefined for `button-*`, `pill-nav`, `game-tile`, `shop-item-card` and `floor-tile`. Only "out-of-stock greyed" is described (DESIGN.md § Components). *Fix:* Add disabled/pressed tokens (e.g. `text-disabled`, `surface-pressed`) and one line per component.
- **medium** `components.scrim.gradient` uses pseudo-syntax (`@92% → @15% at 55%`) that no resolver or CSS can consume. `floor-tile.state-bar: '3px, colour = state-*'` is not a token reference either (DESIGN.md frontmatter `components.scrim`, `components.floor-tile`). *Fix:* Write the scrim as real CSS with `rgba()` stops derived from `scrim-base`. Express the state bar as `width: 3px` + `color: '{colors.state-<state>}'`.
- **medium** No type ramp is assigned to the Kitchen display (the "seat number large" size is undefined), the Owner phone app or the Pi TV/QR pages. Only `web-display`/`web-body` exist for web, and there are no web title/label roles (DESIGN.md § Typography; frontmatter `typography`). *Fix:* State which ramp each of these surfaces uses (e.g. Kitchen = hub ramp + a `kitchen-seat` numeric role; Owner phone = hub ramp). Add `web-title`/`web-label` if owner web needs them.
- **medium** `status-badge` has no colour mapping: it is unclear whether the state colour is the fill (with which ink?) or the text on `hub-tile`. The stated ratios imply text-on-tile, but the component token defines no colours (DESIGN.md frontmatter `components.status-badge`; § Components). *Fix:* Specify `foreground: '{colors.state-*}'`, `background: '{colors.hub-tile}'` (or the fill variant with an `on-*` ink and its contrast).
- **low** Shadows (`0 10px 30px black @35%` etc.) and kiosk geometry (top bar 32/64px, hero ≈980px, tiles ≈140×196 / 190×260, rail ~88px, header ~72px) are literals in prose, not tokens (DESIGN.md § Elevation & Depth, § Layout & Spacing, § Components). *Fix:* Add an `elevation` group (or component tokens) for the three shadows, and component tokens for tile sizes.
- **low** `uppercase` for `kiosk-eyebrow` and `hub-micro` lives only in prose. HC contrast ratios are not stated (DESIGN.md frontmatter `typography`; § Colors HC paragraph). *Fix:* Add `textTransform` notes to the tokens, and one line confirming that the HC pairs meet AAA/AA.

## 3. Component coverage — thin
Checked: every component named in either spine. All 29 DESIGN.md components (button-primary/secondary/warning, scrim, login-panel, pill-nav, pill-nav-item-active, time-chip, account-menu, hero, game-tile, game-tile-featured, filter-rail, shop-item-card, card, hud-pill, hud-toast, lock-screen, hub-rail, hub-header, floor-tile, tile-sheet, inline-pin, chip-rule, chip-offline, status-badge, kitchen-ticket, logo-slot, ad-banner) have rows in EXPERIENCE.md § Component Patterns with real rules. The problem is the UI that the flows and IA name but neither spine specifies.
### Findings
- **high** No text-input / field component, although it is used by login (username + password), the Hub phone-lookup field (Journey 2 step 1), filter-rail search, the shift-close counted-cash entry, the reason picker, the Kiosk/IP manual entry and onboarding forms (DESIGN.md § Components; EXPERIENCE.md § Component Patterns). *Fix:* Add `text-field` (staff and player variants: fill, border, focus, error, label placement) and `select/reason-picker`, with behavior rows covering validation and inline error placement.
- **high** Core Hub staff surfaces outside the floor view have no components. These are the POS product grid / cart / settle bar (the "POS: product grid left, cart right, settle bar bottom" layout), the payment-method split and UPI QR panel, the bill breakdown, the shift-close sheet with the denomination counter and variance display, and the Players profile with outstanding-first. Journeys 2, 5 and 7 depend on them (DESIGN.md § Layout & Spacing Hub bullet; EXPERIENCE.md § Key Flows 2, 5, 7). *Fix:* Add `pos-product-grid`, `cart`, `settle-bar`, `payment-split`, `upi-qr-panel`, `bill-breakdown`, `variance-readout`, `denomination-counter` and `player-lookup` to both spines (visual + behavior), or explicitly state that they compose from existing primitives and say how.
- **medium** Kiosk-side components named in flows but unspecified: the plan picker (only `card` is mentioned), extend-options sheet ("options priced live by the Hub"), Hub-approval waiting, "Pay at counter" lock variant, cart/checkout in Shop, and order-status display (EXPERIENCE.md § Key Flows 3, 4; § IA Kiosk). *Fix:* Add rows for `plan-picker`, `extend-options` and `kiosk-cart`, and the `lock-screen` variants (time-up grace / pay-at-counter / admin).
- **medium** Owner app, onboarding and partner portal have no components. Missing pieces include the figure with data age, the command row with `status-badge`, the alert list, the onboarding pairing-code display (8-char + QR + 15-min countdown) and the referral list/payout table (EXPERIENCE.md § IA Owner/Onboarding/Partner rows; § Key Flows 1, 6, 9). *Fix:* Add `metric-figure`, `command-row`, `pairing-code`, `wizard-stepper` and `data-table` at minimum.
- **low** "Ready-order badge" / "ready badge" and "order badge" are referred to as on-tile UI but are not named components (DESIGN.md § Components floor-tile; EXPERIENCE.md § State Patterns, Journey 4 step 6). *Fix:* Name it (e.g. `tile-order-badge`) and use that name everywhere.

## 4. State coverage — thin
Checked each IA surface against empty / cold-load / loading / focus / error / offline / permission-denied / tier-gated. Covered: the six floor-tile states, cloud offline, Owner data age / pending / expired, the media fallback chain, kiosk and Hub cold load, empty Games/Apps / Shop / Kitchen column / Owner Alerts, plan refusal, credit block, login lock, printer offline, Hub idle lock, and generic inline save error.
### Findings
- **high** The floor-tile state model leaves out states the sources require. **Unassigned** (a new kiosk "appears on the floor view as unassigned", Journey 1 step 6 / PRD Device registry) is missing. So are **Paused** (PRD Sessions "Pause / resume", not billed) and console devices. Device **group colour** (PRD Floor view "groups by colour") has no stated relation to the state colours (EXPERIENCE.md § State Patterns floor tile table; DESIGN.md `state-*`). *Fix:* Add `unassigned` and `paused` states (token + label + tap action, with HC pairs). State how group identity shows without competing with state colour (e.g. a zone header label, never colour).
- **high** Kiosk behaviour while its Hub is unreachable is undecided, even though Journey 8 promises "running sessions continue — no player notices". A player-facing state with no answer will be invented per developer (EXPERIENCE.md § State Patterns "Hub unreachable" `[NOTE FOR UX]`). *Fix:* Decide this: the timer keeps counting locally, the HUD stays silent for N seconds and then shows "Reconnecting to counter…", login/orders are refused with a stated copy line, and reconcile on reconnect.
- **high** Tier-gated presentation (hidden vs locked with an upgrade prompt) is undecided for every surface: Kitchen on Free, the kiosk Shop on Free (Open Q1), the Owner app on Free and Premium Live view (EXPERIENCE.md § Tier Gating in UI `[NOTE FOR UX]`). *Fix:* Pick one rule per mood (e.g. staff surfaces show locked + upgrade link; player surfaces hide) and add a `tier-locked` state row.
- **medium** Hub rail surfaces other than the floor view (POS, Players, Sessions, Inventory, Shift, Reports, Settings, System) have no states. Missing: player-lookup no-match, empty cart, stock out / expired item at POS, low-stock/expiry alerts, standby/backup status, and an RBAC permission-denied state for a role without a permission that is not PIN-elevatable (EXPERIENCE.md § State Patterns). *Fix:* Add one row per surface for empty/no-match/error. Add a "not permitted for your role" treatment distinct from `inline-pin`.
- **medium** Missing kiosk states: waiting for Hub approval after plan pick, sign-up duplicate refusal, extend refused past closing time (PRD Sessions Extend), blocked-process message (PRD Process control), forced-end message (PRD Sessions Forced end), and staff broadcast message (EXPERIENCE.md § State Patterns; § Component Patterns `hud-toast`). *Fix:* Add rows with copy in the Player register.
- **medium** No offline/disconnect state for the Kitchen display (LAN loss), the Owner phone app (no network), or the onboarding wizard resume ("resumable at every step"). There is also no empty state for the Partner portal (no referrals yet) (EXPERIENCE.md § State Patterns). *Fix:* Add one row each.
- **medium** Screen-reader semantics are absent. Nothing defines how live floor-tile updates, `hud-toast`, kitchen arrivals or `chip-offline` announce (aria-live/role), and OS reduced-motion is not honoured (only HC reduces motion) (EXPERIENCE.md § Accessibility Floor). *Fix:* Add announcement rules for the live regions, and "honour OS reduced-motion on all surfaces".

## 8. Shape fit — adequate
